RAG 入门知识库
==============

一、RAG 是什么

RAG 是 Retrieval-Augmented Generation 的缩写，中文叫检索增强生成。它的核心思路只有八个字：先检索，再生成。用户提问以后，程序先去知识库里找出与问题最相关的几段资料，再把这些资料和问题一起交给大模型，让模型基于资料来回答。没有检索这一步，模型只能靠训练时记住的内容作答，遇到知识库里的私有资料、最新资料，它要么答不上来，要么编一个听起来很像的答案，这就是幻觉。有了检索，模型的回答就有了依据，能指出来源，幻觉会明显减少。

二、为什么企业需要 RAG

企业的知识大多放在文档、手册、工单、数据库里，这些内容不会出现在模型的训练数据中。把这些文档重新训练进模型，成本高、周期长，而且资料一改动就得重训。RAG 不需要训练，只要把文档切好、建好索引，改动一份文档只影响那一份，第二天就能生效。这就是 RAG 成为企业落地最主流方案的原因：成本低、更新快、可溯源。

三、文档切分为什么重要

一整本书几万字，没法直接塞给模型；就算塞得进去，里面百分之九十的内容和当前问题无关，反而会干扰模型。所以第一步要把长文档切成一段一段，每一段叫一个 chunk。切分的好坏，直接决定检索能不能找准。切得太碎，一句话被拦腰截断，前半句在上一段、后半句在下一段，检索到任何一段都只拿到半句，模型答不完整。切得太大，一段里混着好几个主题，向量会被稀释，检索时容易召回一大堆不相关的内容。合适的长度通常在几百字，具体数字要看文档类型，技术文档可以小一些，叙述性文字可以大一些。

四、为什么要让相邻两段重叠

如果完全按字数硬切，一定会有一句话正好跨在切点上。解决办法是让相邻两段重叠一部分，常见的是重叠五十到一百字。这样切在边界上的那句话，至少有一段是完整的。重叠的代价是有少量内容重复出现两次，检索时可能命中两段相似的内容，但相比丢掉半句话，这点重复是可以接受的。

五、Embedding 是什么

Embedding 就是把文本变成一串数字。模型读一句话，输出一个固定长度的向量，比如五百一十二个数字。这句话的意思被压缩进了这串数字里：意思相近的两句话，向量方向接近；意思无关的两句话，向量方向差得远。这样一来，判断两句话像不像，就从文字比对变成了数学计算。文字比对只能找到字面相同的词，今天天气很好和今儿个天气不错几乎没有一个字相同，但意思一样；而向量能把这种相似性算出来。

六、余弦相似度怎么理解

余弦相似度衡量的是两个向量的方向夹角。结果等于一时，方向完全一致；等于零时互相垂直，毫无关系；等于负一时方向相反。它完全不看向量的长度，只看方向。公式是把两个向量的点积，除以两个向量长度的乘积。除以长度这一步，就是为了把长度的影响消掉，只留下方向的信息。

七、向量检索和关键词检索的区别

关键词检索统计字面是否出现。用户搜苹果，它找包含苹果两个字的段落，搜不到写成 iPhone 的文章。向量检索比的是意思，用户问怎么减少胡说八道，它能找到讲幻觉抑制的段落，即使那段里没有胡说八道这四个字。两者各有盲区：向量检索对精确的型号、编号、人名不敏感，关键词检索对同义表达无能为力。所以工程上常把两种结果合并，叫混合检索。

八、常见向量库怎么选

数据量小的时候，直接用内存里的数组做暴力检索就够了，几百上千段文档，逐个算相似度也就毫秒级。数据量上去以后要用专门的向量库，FAISS 是本地库，不需要服务，适合原型和单机场景；Milvus、Qdrant 这类是服务化的，支持分布式、动态增删、多用户隔离。选型时先看数据量和是否需要多机，不要一上来就上重型方案。

九、幻觉怎么抑制

第一种是提示词约束，明确告诉模型只依据提供的资料回答，资料里没有就说不知道，不要自己推测。第二种是引用溯源，要求模型在答案后面标注来源编号，程序再把编号换成文件名和原文片段，用户可以点开核对。第三种是检索不到就拒答，相似度低于阈值时直接告诉用户没有找到相关资料，而不是硬凑一个答案。这三条配合起来，效果比单独用任何一条都稳。

十、RAG 怎么评估

要看两个指标。召回率看检索出来的段落里，有没有包含真正答案的那一段；准确率看检索出来的段落里，有多少是真正相关的。召回率低说明切分或向量模型有问题，准确率低说明需要重排序。工程上的做法是准备几十个问题、标好正确答案在第几段，每次改参数都重新跑一遍，用数字对比而不是凭感觉说变好了。这些数字在面试时也是最有说服力的部分。

十一、Transformer 的注意力机制在做什么

注意力机制做的事情是：句子里的每个词，去看句子里其他所有的词，判断哪些词跟自己关系大，然后把那些词的信息按重要程度揉进自己身上。举个例子，句子里的它指代前面某个名词，模型靠注意力找到那个名词并把信息拿过来。这正是 Transformer 比循环神经网络强的地方：它可以一步看到全句，不用一个词一个词往后传。

十二、为什么要多头注意力

一组注意力只能学会一种关系。有的注意力关注指代关系，有的关注修饰关系，有的关注动宾关系。多头就是并行跑好几组注意力，每组有自己的参数，各自关注不同的关系，最后把结果拼起来。一组注意力像一个视角，多头就是多个视角同时看同一句话。

十三、位置编码解决什么问题

注意力本身是一次性看全句的所有词，它不知道谁在前谁在后。把同一句话打乱顺序，注意力算出来的结果是一样的，这显然不对。位置编码就是给每个词额外加一个表示位置的信号，让模型知道这个词在原句里排第几。没有它，模型分不清我打他和他打我。

十四、残差连接解决什么问题

神经网络层数一多，训练时梯度从后往前传，越传越小，传到前面几乎变成零，前面的层就学不动了，这叫梯度消失。残差连接的做法是把这一层的输入直接加到输出上，相当于给梯度开了一条捷径，让它能绕过多层直接传回去。这一条捷径是深层网络能训起来的前提。

十五、Function Calling 是什么

大模型本身不会执行任何函数，它只会输出文字。Function Calling 的机制是：你先把有哪些工具、每个工具要什么参数，用结构化格式告诉模型；模型判断需要调用某个工具时，不直接回答，而是输出一段结构化的调用请求，写清楚调用哪个函数、参数是什么；你的程序拿到这段请求，真的去执行函数，再把执行结果喂回给模型；模型最后用自然语言总结。整个过程里，模型只负责决策，执行永远在你的代码里。

十六、ReAct Agent 的循环是什么

ReAct 是推理加行动的组合。一个 Agent 循环通常长这样：先思考当前该做什么，然后选择一个工具去执行，拿到执行结果作为观察，再根据观察继续思考下一步，直到任务完成或者达到最大步数。必须加两个保护：最大步数限制，防止模型在死循环里反复调用同一个工具；工具失败时的重试或降级，防止一个接口挂了整个任务卡死。

十七、MCP 和 Function Calling 是什么关系

Function Calling 解决的是调用机制：模型怎么表达我想调哪个函数、参数是什么。MCP 解决的是协议标准：本地有哪些能力可以暴露给模型，用统一的格式描述，让不同的框架、不同的模型都能接同一套工具。前者是动作，后者是插头标准。没有 MCP 时，换一个框架就要重写一遍工具接入；有了 MCP，工具写一次到处能用。

十八、微调和 RAG 怎么选

RAG 解决的是知识问题：模型不知道的私有资料、最新资料，用检索补进去。微调解决的是行为问题：让模型学会固定的输出格式、特定的说话风格、某个领域的判断习惯。判断口诀是：缺知识用 RAG，缺格式用微调。两者也能叠加，先用微调把格式教会，再用 RAG 补知识。成本上，RAG 只需要建索引，改一份文档就生效；微调要准备数据、要跑训练、要重新部署，周期长得多。

十九、大模型推理为什么快

关键在于 KV Cache。模型生成回答时是一个词一个词往外吐的，每吐一个新词，都要把前面所有词重新算一遍注意力。如果每次都重算，第二个词算一遍、第三个词算两遍，浪费极大。KV Cache 的做法是把每个词算出来的键和值缓存下来，后面算新词时直接取用，不再重算。代价是显存占用随上下文长度增长，用显存换时间。

二十、PagedAttention 解决什么问题

KV Cache 的显存占用不规则，有的请求上下文长、有的短，如果按最长的那条预留空间，会浪费大量显存，还会产生碎片。PagedAttention 借鉴操作系统的分页思想，把 KV Cache 切成固定大小的块，按需分配，不连续的块也能拼起来用。显存利用率上去了，同样一张卡能同时服务的请求数就多了，吞吐量因此提升。

二十一、量化是用什么换什么

量化是把模型权重的数值精度降低，比如从十六位浮点降到八位整数甚至四位。精度降低以后，权重占的显存变小，读取权重需要的带宽也变小，推理更快、更省卡。代价是数值精度损失，模型能力会有轻微下降，通常降到八位影响很小，降到四位就要看任务类型。一句话总结：用量化换显存和带宽。

二十二、LangChain 这类框架解决什么

框架把常见流程封装成组件：文档加载器、切分器、向量库封装、检索链、提示词模板。好处是搭得快、换组件方便；坏处是出问题时你不知道它内部做了什么。对于要讲清楚原理的场景，手写一遍再对比框架，比直接调框架更有说服力。面试官问为什么不用框架时，正确答案不是框架不好，而是这个规模下手写更可控、更容易定位问题。

二十三、一个 RAG 系统的完整链路

第一步加载文档，第二步切分成 chunk，第三步每个 chunk 算 embedding，第四步把向量存进向量库，第五步用户提问时把问题也算成向量，第六步在向量库里找最像的若干 chunk，第七步把问题和这些 chunk 拼成提示词，第八步调用大模型生成答案，第九步把答案和引用来源一起返回。这条链路上任何一环出问题，最终表现都是答不准，所以排查时要一环一环看，而不是一上来就怀疑模型不行。
